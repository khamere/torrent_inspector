# Security policy

## Scope

This policy covers the public standalone Torrent Inspector userscript and its published website. It does not cover tracker websites, their accounts, browsers, or userscript managers.

Proposed maintenance scope: investigate reports against the latest published standalone release. Older releases may need an update before a fix is assessed. 

## Report a vulnerability

Preferred channel: enable and verify GitHub private vulnerability reporting for this repository, then use **Report a vulnerability** from its Security area.

If that option is unavailable, open an issue asking only for a private security contact. Do not include vulnerability details or a proof of concept in that public issue. A maintainer should establish a private channel before receiving those details.

Include the affected version, a description of the impact, reproduction steps using non-sensitive data, and any proposed fix. Do not include passwords, cookies, tokens, or another user’s private information.

## Handling reports

The maintainer will assess the report and coordinate any fix and public disclosure with the reporter. This draft does not promise a response deadline, patch schedule, or bounty.

Ordinary naming errors, missing controls, and other non-security bugs belong in the normal issue templates.
